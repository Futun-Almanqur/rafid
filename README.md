## What this is

Rafid is a bilingual (Arabic-majority) student-services assistant for **Wadi
University** (جامعة الوادي), a fictional Saudi university. It answers questions
about campus services — transcripts, enrolment letters, fees, withdrawals,
graduation clearance — grounded strictly in a service directory, and it refuses
rather than guessing when a fact is not in that directory.

It does three things a chat wrapper does not:

- **It is grounded.** Answers are composed from a service directory. A fee that
  is not in the directory cannot appear in an answer.
- **It acts, under authorisation.** Four tools spanning three risk classes. The
  side-effecting one — booking an advisor appointment — passes an authorisation
  gate that reads the *authenticated session*, never the conversation. So does
  the private read-only one: **read-only does not mean unauthenticated.**
- **It refuses.** A layered input wall and an outbound wall, both bilingual,
  measured on two numbers that are always reported together: how much of an
  attack corpus is blocked, and how much of a legitimate corpus is blocked by
  mistake.

Every one of those claims has a cell behind it in the notebook.

## How to open and run it

**The notebook is the submission.** It runs in Google Colab with no API key
required by default, no manual clone, and no local installation.

1. Open `notebook/capstone.ipynb` in Colab.
2. **Runtime → Run all.**

The first cell does the setup itself: it clones this repository, installs its
pinned dependencies, and starts a local backend on a free port. That clone is
performed by the notebook, not by you — the requirement is zero *manual* setup,
and the setup cell is what delivers it. Nothing else is required. If a stranger
opens the notebook link and hits Run all, they reach a working bilingual
conversation — that is the reproducibility proof, and there is no CI pipeline
standing in for it.

### Running it locally instead

```bash
git clone <this repository> && cd rafid
python -m venv .venv && .venv/bin/pip install -r requirements.lock
python scripts/run_gateway.py                 # the local backend
.venv/bin/pytest                              # the test suite
```

## The write-up — one paragraph per rubric section, written from the results

**1 · Architecture and the model boundary.** One `LLMClient` protocol, two
dialect adapters and a `FakeClient`, all confined to `src/rafid/llm/`. Routes are
configuration: `build_client(settings, "primary")` and
`build_client(settings, "onprem")` differ by a name, and no branch anywhere reads
a provider. I chose the wire contract over the vendor SDKs (ADR 005) because we
already have retries and typed models above the boundary, and because the wire
does not churn between minor versions — then added a negative control to each
architecture test so the claim is not vacuously true. Both fault drills fire real
faults at a real socket: three 429s with `Retry-After` honoured and the same route
serving on attempt 4, and a 529 outage where retries exhaust and the open-weight
route serves the student.

**2 · Structured outputs and function calling.** `StudentRequest` is strict —
enums, patterns, `extra="forbid"` — and rejects an invented field, a campus
outside the enum and a malformed identifier. Extraction is validate → retry →
repair, and the repair turn re-reads the original message rather than the
validation feedback, because extracting from the error produces a request object
about the error. Four tools span three risk classes, and the authorisation gate
reads a **declared** `auth_policy`, never the risk class. That correction came out
of a contradiction in my own first design (ADR 006): the old rule gated the
terminal escalation and would have left a private read-only lookup open.

**3 · Prompt pipeline and guardrails.** Six prompt ids as versioned files with
changelogs and a canary; rendering with a missing variable raises at build time.
The five stages each run alone in a test. Normalisation happens before pattern
matching, which is what catches the fullwidth and Arabic-presentation-form
attacks — and which caused a real bug, since our fold silently broke an unfolded
keyword list downstream. Guards score **100% blocked on 40 attacks and 0% false
positives on 40 legitimate messages**, from one run. The first run scored 95.0% —
at target with no margin — and named its two misses; both were real exfiltration
shapes, and the fix cost no false positives.

**4 · Evaluation harness.** 48 cases, every stratum ≥ 8, Arabic-majority, safety
oversampled. The harness calls the same `build_assistant` the demo uses — there is
no second request path in the project. Result: 48/48, every slice 100%, safety
green. Judge calibration moved κ from 0.65 to 0.96 on a **rubric** edit; I report
plainly that v1 already cleared the bar and was miscalibrated in two nameable
ways rather than unusable. The gate blocks a seeded regression and names five
slices — `difficulty=edge` fell 30 points while the overall average moved 6.

**5 · Cost and latency.** Meter first: 613 calls seen, 613 metered, 100%, with
the guard and router stages in the number. Then optimise, one lever at a time,
every row carrying its gate verdict. 96.9% reduction against a 60% target. The
semantic threshold was chosen from data, and my first sweep was wrong — pairwise
comparison reported zero wrong hits where the live cache found one. Cost figures
in this repository are labelled **COLAB VERIFICATION PENDING**, because the build
environment could not load the real tokenizer.

**6 · Model comparison and recommendation.** Both backends over our own golden
set, sliced, with cost and latency beside quality. The open-weight route loses
most on safety (81%) and Arabic (92%) — which is what shapes the routing table,
not the average. The break-even quotes both commercial tiers and carries a caveat
I will not bury: throughput measured against a latency-compressed simulator
describes our harness, so the arithmetic is correct in form and unusable as a
capacity claim until re-run on a real model.

**7 · The application, complete.** The demo shows five things as captured output:
a grounded Arabic answer, a booking that really happens, a refused attack that
does not echo the payload, a cross-student refusal made by the session rather
than the model, and a fallback that served the student while the primary model
was returning 529. The one thing not yet demonstrated is the Colab run itself —
see below.
